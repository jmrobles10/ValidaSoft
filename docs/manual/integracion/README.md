# Integración

API, llaves, sistemas integradores, webhooks, eventos, sandbox, SSO de sistemas e importación.

- [Crea una API key con sus permisos y empresas, rótala y revócala](api-keys.md) — Administrador de empresa. La administradora emite una clave para que un sistema llame a la API: elige sus permisos y las empresas a las que alcanza, ve la clave una sola vez, la rota con un periodo de solapamiento y, al final, la revoca.
- [Lee y vacía el buzón de correo de pruebas](buzon-de-pruebas.md) — Sistema integrador. En el sandbox, los correos que Validasoft enviaría no salen a nadie: quedan en un buzón. El sistema integrador lista ese buzón, abre un correo para ver su contenido y lo vacía cuando termina sus pruebas.
- [Consulta la certificación de un proveedor con ETag](consulta-de-certificacion.md) — Sistema integrador. Un ERP consulta si un proveedor tiene certificado vigente. Guarda el ETag de la respuesta y la próxima vez lo manda en If-None-Match: si nada cambió, recibe 304 y se ahorra el cuerpo; si el vínculo se bloqueó, la respuesta trae la versión nueva.
- [Lee los eventos por pull o en vivo con un cursor](eventos-pull-y-en-vivo.md) — Sistema integrador. El sistema integrado pide los eventos de un tipo desde el último cursor que conoce, y guarda el nuevo cursor para la siguiente vez. Si prefiere tiempo real, abre el flujo de eventos (SSE) y se reanuda con Last-Event-ID si se corta.
- [Entra a una persona de tu sistema con identidad delegada](identidad-delegada.md) — Sistema integrador. Tu sistema firma una aserción con su clave privada que dice quién es la persona, la envía con su llave de API y Validasoft devuelve una sesión de 30 minutos con los permisos de esa persona. Cada aserción vale una sola vez: para la siguiente petición, tu sistema firma otra.
- [Importa terceros desde el Portal de proveedores](importar-del-portal.md) — Plataforma. El operador de Plataforma lanza una importación desde el Portal de proveedores: primero una simulación que no escribe nada y luego la importación real. Al terminar, la corrida muestra cuántos terceros se crearon, cuántos ya existían y qué datos quedaron con advertencia o rechazados.
- [Invita a un proveedor desde tu sistema con la API](invitar-por-api.md) — Sistema integrador. El ERP del cliente crea el vínculo con un POST a la API, con el tercero, su correo y su propia referencia. Validasoft envía la invitación y el vínculo aparece en la lista de la empresa, con esa referencia para buscarlo después.
- [Prueba la integración en el sandbox antes de producción](sandbox.md) — Sistema integrador. El sistema integrador emite una llave de prueba, que crea el sandbox del grupo: una copia de sus empresas aislada de los datos reales. Ahí invita a un proveedor sin que salga ningún correo real, revisa el buzón de pruebas y, al final, reinicia el sandbox para empezar de cero.
- [Registra un sistema integrado con su clave pública](sistema-integrador.md) — Administrador de empresa. La administradora registra un sistema externo (un ERP, un portal) con su código, su nombre, su clave pública y los sitios desde los que se incrusta Validasoft. Desde ese momento las personas pueden entrar desde ese sistema.
- [Revisa una entrega fallida y la reenvía cuando el sistema vuelve](webhook-entrega-fallida-y-reenvio.md) — Administrador de empresa. Tu sistema responde con error y Validasoft deja la entrega en reintento, con su próximo intento. Cuando el sistema se recupera, la administradora reenvía la entrega desde la pantalla y llega firmada otra vez.
- [Crea un webhook, guarda su secreto y revisa las entregas firmadas](webhooks.md) — Administrador de empresa. La administradora registra la dirección de su sistema para que Validasoft le envíe cada evento con un POST firmado. Guarda el secreto una sola vez, y luego revisa en la pantalla las entregas, con sus intentos.
